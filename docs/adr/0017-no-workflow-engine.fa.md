# ADR-0017: بدون workflow engine

- وضعیت: Accepted
- تاریخ: `2026-11-16`
- مرتبط: [ADR-0001](0001-system-boundary.md)، [spec 05](../specs/05-expiry-and-effective-state.md)

## زمینه

holdها و انتظارها مهلت دارند و این به نظر می‌رسد به timerهای پایدار (durable) نیاز داشته باشد.

## تصمیم

چرخهٔ عمر درخواست هفت حالت و دو timer دارد. یک ماشین حالت در پایگاه داده به‌همراه یک sweeper کافی است. از workflow engine استفاده نمی‌کنیم.

## گزینه‌های بررسی‌شده

| گزینه | نتیجه |
| --- | --- |
| ماشین حالت در PostgreSQL + sweeper | **انتخاب‌شده** |
| Temporal، Camunda یا مشابه آن‌ها | رد شد. یک cluster چندسرویسی با پایگاه دادهٔ مستقل خودش را به مسیر حیاتی اضافه می‌کند. |
| کلیدهای TTL در Redis یا یک cron job برای هر رزرو | رد شد. رویدادهای انقضا ممکن است گم شوند؛ cron با confirm دچار race می‌شود. |

## پیامدها

- دقت timer برابر با بازهٔ اجرای sweeper است (1 s)، و درستی سیستم به آن وابسته نیست چون خواندن‌ها حالت مؤثر (effective state) را محاسبه می‌کنند.

## چه زمانی بازنگری شود

وقتی orchestration ایجاد سرویس وارد محدودهٔ سیستم شود ([ADR-0001](0001-system-boundary.md))؛ در آن صورت workflow engine ابزار درست است.
