# ADR-0014: REST با OpenAPI و Problem Details

- وضعیت: Accepted
- تاریخ: `2026-11-16`
- مرتبط: [spec 01](../specs/01-api.md)، [PRD A-16](../prd/PRD.md#7-assumptions)

## زمینه

مصرف‌کننده‌ها عبارت‌اند از پنل مشتری، اتوماسیون مشتری (Terraform providerها، اسکریپت‌ها) و سرویس‌های داخلی. اتوماسیون به خطاهای قابل خواندن توسط ماشین و retryهای امن نیاز دارد.

## تصمیم

- REST روی JSON زیر `/v1`، با OpenAPI 3.1 که از روی endpointها تولید می‌شود.
- خطاها به‌صورت RFC 9457 Problem Details با یک `code` پایدار و `retryable`.
- هدر `Idempotency-Key` روی هر mutation؛ cursor pagination.
- هویت از هدرهای gateway (`X-Customer-Id`، `X-Actor-Kind`، `X-Actor-Id`)؛ احراز هویت خارج از محدوده است.

## گزینه‌های بررسی‌شده

| گزینه | نتیجه |
| --- | --- |
| REST + OpenAPI | **انتخاب شد.** برای همهٔ مصرف‌کننده‌ها کار می‌کند، از جمله ارزیاب با `curl`. |
| فقط gRPC | رد شد. برای ابزارهای مشتری و ارزیابی اصطکاک ایجاد می‌کند. می‌توان آن را برای سرویس‌های داخلی روی همان لایهٔ application اضافه کرد. |
| GraphQL | رد شد. API فرمان‌محور است؛ queryهای انعطاف‌پذیر چیزی اضافه نمی‌کنند. |

## پیامدها

- یک فایل قرارداد برای همهٔ مصرف‌کننده‌ها؛ CI آن را با سند OpenAPI commitشده مقایسه می‌کند.

## چه زمانی بازنگری شود

وقتی حجم یا تأخیر فراخوانی‌های داخلی، gRPC را به‌صرفه کند.
