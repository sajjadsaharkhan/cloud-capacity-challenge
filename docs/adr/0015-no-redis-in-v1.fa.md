# ADR-0015: بدون Redis در نسخهٔ اول

- وضعیت: Accepted
- تاریخ: `2026-11-16`
- مرتبط: [ADR-0012](0012-database-postgresql.md)، [spec 07 §6](../specs/07-quotas-and-fairness.md#6-rate-limits)

## زمینه

cache کردن سطح‌های ظرفیت، negative cache برای sold-out و محدودیت‌های نرخ، دلایل معمول اضافه کردن Redis هستند.

## تصمیم

بدون Redis. snapshot ظرفیت حدود 90 کلید است (3 منطقه × حدود 30 محصول) که به مدت 2 ثانیه درون process cache می‌شود؛ با این فاصله، هر instance از API حداکثر حدود 45 بار در ثانیه برای آن به پایگاه داده query می‌زند، مستقل از ترافیک خواندن. cache مربوط به sold-out و محدودیت‌های نرخ به ازای هر instance هستند.

## گزینه‌های بررسی‌شده

| گزینه | نتیجه |
| --- | --- |
| cacheهای درون process | **انتخاب شد.** یک وابستگی کمتر یعنی یک failure mode کمتر. |
| Redis برای cache و محدودیت‌های نرخ | فعلاً رد شد؛ در مسیر رشد قرار دارد. |
| Redis روی مسیر درستی (counterها، قفل‌ها، idempotency) | در هیچ نسخه‌ای پذیرفته نیست ([ADR-0004](0004-concurrency-control.md)، [ADR-0006](0006-idempotency.md)، [ADR-0012](0012-database-postgresql.md)). |

## پیامدها

- محدودیت‌های نرخ تقریبی هستند: محدودیت‌های per-instance در تعداد instanceها ضرب می‌شوند.
- instanceهای مختلف ممکن است سطح‌های ظرفیت را با اختلاف حداکثر 2 ثانیه ارائه دهند.

## چه زمانی بازنگری شود

بیش از 10 instance از API، یا نیاز به محدودیت‌های نرخ سراسری و دقیق که gateway نتواند فراهم کند. حتی در آن صورت هم Redis بیرون از مسیر درستی می‌ماند.
